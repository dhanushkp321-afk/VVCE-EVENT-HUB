# VVCE Events Hub — Complete Codebase Audit & Notes

> **Audit Scope:** Full read-only review of frontend pages, routing, forms, buttons, modals, backend API (`api/send-otp.js`), Supabase database schema/sync, role security (Student, Club Admin, Approving Authority, CPM Admin), and scalability for **5,000–6,000 students**.
> **No source code was modified during this audit.**

## Section A: Mistakes & Bugs Found by AI

### 1. Application Architecture, Routing & Dead Code
- **Broken/Duplicate Route in `js/core/router.js` (`L122-L123`)**
  - The `renders` map inside `showPage()` defines `'dean-portal'` twice: first pointing to `renderAuthorityPortal()`, immediately overwritten by `renderDeanPortal()`.

- **Unconnected `pages/*.html` Templates (`pages/` directory)**
  - `index.html` (`L461-L496`) uses empty `<div class="page" id="page-...">` containers populated at runtime via `innerHTML` in `js/pages/*.js`. None of the 13 files in `pages/*.html` are loaded by `index.html` or `scripts/build.js`.
  - Worse, `pages/*.html` call **non-existent JS functions** and reference mismatched DOM IDs and CSS classes:
    - `pages/clubs-directory.html` calls `filterClubDomain(...)` (undefined).
    - `pages/create-event.html` calls `checkEventVenueClash(...)` (undefined) and `submitDraftEvent()` with no `id` arg (in `manage-events.js`, `submitDraftEvent(id)` expects an event ID).
    - `pages/events-feed.html` calls `setEventCategory(...)` (undefined).
    - `pages/manage-events.html` calls `filterManageEvents(...)` (undefined).
    - `pages/participants-attendance.html` calls `exportParticipantsCSV()`, `openQRScannerModal()`, `filterParticipants()`, `handleManualCheckIn()` (all undefined in `js/pages/participants.js`).
    - `pages/my-registrations.html` uses tabs `'attended'` and `'cancelled'`, while `js/pages/registrations.js` (`switchRegTab`) expects `'upcoming'`, `'pending'`, `'past'`.
- **Legacy Orphaned Files & Bloat in Repository**
  - Legacy pre-modularization files remain in `js/`: `js/auth.js`, `js/data.js`, `js/student.js`, `js/supabaseClient.js`.
  - `app.js` (394 KB) is generated by `scripts/build.js` (`npm run build`), yet `index.html` (`L927-L950`) loads the individual `js/core/*.js` and `js/pages/*.js` files instead of `app.js`.
  - `dist/` contains stale Vite-style build artifacts (`dist/index.html`, `dist/assets/...`) unused by Vercel (`vercel.json` sets `"outputDirectory": "."`, `"buildCommand": null`).
  - `eng.traineddata` (5.2 MB) is duplicated in both the project root and `assets/eng.traineddata` (10.4 MB total) from the removed Tesseract OCR feature, alongside duplicated `vvce-logo-header.png`.
  - `index.html` (`L13`) loads `@emailjs/browser@4` CDN script even though `emailjs` is never referenced anywhere in the codebase. `index.html` (`L9`) also loads `html5-qrcode` only for removed ID card barcode scanning (`#reader-hidden`).
- **Missing CSS Classes (`style.css` vs `index.html` / JS)**
  - `.authority-lock` (`index.html:517`) has no `.authority-lock .portal-lock-icon` rule in `style.css` (only `.dean-lock` and `.principal-lock` exist), leaving the Approving Authority modal icon unstyled.
  - `.btn-sm` is used in `authority-views.js` (`L368, L664`), `authority-portal.js` (`L284-285, L399-400, L449`), and `cpm.html` (`L2016, L2019`) without any `.btn-sm` CSS rule in `style.css` or `cpm.html`.

#### Detailed Auth & Security Bugs
1. **Unauthenticated Account Takeover via Password Reset (`auth.js:1104-1109, 1152`)**:
   - `sendResetVerificationCode()` prints the generated 6-digit `code` directly into the modal (`Instant Code: ${code}`). Anyone can enter any student, faculty, or authority `@vvce.ac.in` email, copy the code shown on their own screen, and overwrite that person's password in Supabase.
   - For authorities, `executePasswordReset()` (`L1203-1208`) attempts to write `pass: newPass` (plaintext) to `approving_authorities`, even though `migration_approving_authorities.sql` defines no `pass` column (only `password_hash` and `salt`).
2. **Instant Account Takeover via Google Sign-In Fallback (`auth.js:1350-1410`)**:
   - Because `GOOGLE_CLIENT_ID` is empty (`config.js:23`), clicking "Continue with Google" opens `prompt('Enter your VVCE Google email address:')`. Entering *any* registered `@vvce.ac.in` email (including `dean.sw@vvce.ac.in` or a Club Admin) logs straight into that account (`launchApp(user)`) with no password and no Google OAuth token.
3. **Uncaught `ReferenceError: switchAuthTab is not defined` (`auth.js:669`)**:
   - `finalizeRegistration()` calls `switchAuthTab('signin')` after sending the Supabase verification email. Only `switchMainTab` exists in `js/pages/auth.js`, so every signup throws a console error right after completion.
4. **Dead OCR Code with Undefined Symbols (`auth.js:65-451, 907`)**:
   - `handleFileUpload` calls undefined `parseNameFromOCRText` (`L237`), reads undefined `ocrTextCombined` (`L325, L418`), and accesses removed DOM IDs (`s-verified-usn`, `student-scanner-ui`, `a-verified-usn`, `admin-scanner-ui`, `auth-scanner-ui`). `bypassPrincipalScan()` (`L907`) also toggles removed IDs.

### 3. Student Portal Pages

#### A. Student Dashboard (`js/pages/student-dashboard.js`)
- **Today's Events Counted as Past/Completed (`L14, L77`)**:
  - `new Date(e.date) >= new Date()` compares UTC midnight of `YYYY-MM-DD` (05:30 AM IST) against the current local timestamp. Any event happening *today* disappears from "Upcoming Events" and increments "Completed Events" after 05:30 AM IST.
- **Real-time Theme Ribbon Crash (`js/pages/cpm-theme.js:192-193`)**:
  - `applyCelebrationTheme()` calls `renderDashboard()` when `STATE.page === 'dashboard'`, but the function is named `renderStudentDashboard()`. `renderDashboard` does not exist, so live theme changes do not update the dashboard greeting ribbon.
- **Unused Right Sidebar Space (`L119-L121`)**: Empty commented area above Upcoming Events (leftover from removed Principal Availability widget).

#### B. Events Feed & Team Registration (`js/pages/events.js`)
- **Broken Supabase Waitlist Update (`L1101-L1103`)**:
  - `joinWaitlist()` checks `if (window.sb) { window.sb.from('events').update(...) }`. In the main app, the client is `window.supabase` / `getSupabaseClient()`, NOT `window.sb` (`sb` only exists in `cpm.html`). As a result, waitlist updates rely entirely on `setDB('vvce_events', ...)` — and **`mapEventForSupabase()` in `database.js` does not include `waitlist`**, so waitlist additions are **never persisted to Supabase**!
- **Waitlist Flag Mismatch (`events.js:117`, `clubs.js:150`, `create-event.js`)**:
  - `events.js` checks `ev.waitlist_enabled`, but `create-event.js` provides no toggle or field for `waitlist_enabled` when creating an event (only `cpm.html` has it, and `cpm.html` drops `waitlist_enabled` from `dbPayload` when saving!).
- **Registration Overbooking / Lost Updates (`events.js:1232-1241`, `clubs.js:137-169`)**:
  - Seat capacity checks and `registrations.push(STATE.user.id)` happen in client-side memory before calling `setDB('vvce_events', events)`. Simultaneous registrations by multiple students overwrite each other and can exceed `maxParticipants`.
- **Team Registration Draft Leak & `regCount` Drift (`events.js:237-395, 606-682, 956-976, 1271-1295`)**:
  - Adding the very first teammate in `addTeamMember()` immediately saves the team and adds the leader to `ev.registrations` before the user clicks "Register Team 🚀" (`L325-331`). If the user clicks "Cancel", the draft team and leader registration remain in the database!
  - `removeConfirmedTeamMember()` (`L975`) and `unregisterEv()` (`L1277`) decrement `ev.regCount`, while `eventCard()` computes seats from `(ev.registrations || []).length`, causing `ev.regCount` vs `registrations.length` mismatches across views (`participants.js` vs `events.js` vs `authority-views.js`).
- **Payment Flow Gap (`events.js:1112-1230`)**:
  - `simulatePayment()` renders an external QR code via `api.qrserver.com` and lets the user upload any image screenshot without transaction ID validation or storage bucket upload (stores base64 directly inside `events.pending_payments` JSON).
  - Unregistering (`unregisterEv`) does not check paid status or warn about refunds/team leadership abandonment (a team leader can unregister while leaving their team orphaned).

#### C. Clubs Directory (`js/pages/clubs.js`)
- **Unescaped Apostrophes in Club Tabs (`L46-L47`)**:
  - `switchClubTab('upcoming', '${selectedClubName}')` does not escape single quotes (`'`), whereas `L83` does. A club name containing an apostrophe (e.g., `St. John's Club` or `VVCE's Robotics`) breaks tab switching with a JS syntax error.
- **Unapproved Clubs Appear via Fallback (`L59-L68`)**:
  - `users.filter(u => u.type === 'admin' && u.clubName)` does **not** filter by `u.approved`, so pending or rejected clubs appear in the public Clubs Directory!
- **Duplicate `registerEv(id)` Function (`clubs.js:137-169`)**:
  - `registerEv()` lives inside `clubs.js` instead of `events.js` or a shared module, coupling the Events page (`events.js:120, L1422`) to `clubs.js`.

#### D. Academic Calendar (`js/pages/calendar.js`)
- **Branch Filtering Inconsistency (`L66-L68, L132-L134` vs `L172`)**:
  - `drawCalendar()` and `showCalDateEvents()` filter student events using exact `e.branches.includes(STATE.user.branch)` (ignoring `isBranchMatch()` canonical matching used on Dashboard and Events Feed — e.g., `'CS'` student will miss `'CSE'` events!), while `renderAcadSchedule()` (`L172`) does not filter by branch at all.
- **Fixed Two-Column Grid Not Responsive (`L12`)**:
  - `style="display:grid;grid-template-columns:1fr 300px;gap:1.5rem;"` is inline and lacks a mobile `@media` rule, squeezing the calendar grid on narrow mobile screens (`< 600px`).

#### E. My Registrations (`js/pages/registrations.js`)
- **No QR Entry Ticket Implementation**:
  - Despite `pages/README.md` and `pages/my-registrations.html` advertising "Dynamic QR entry ticket modal", `registrations.js` has no QR pass generation.
- **Same-Day Past Date Bug (`L31`)**:
  - `new Date(e.date) < now` moves today's events into "Past Events" after 05:30 AM IST.

#### F. Certificates (`js/pages/certificates.js`)
- **Orphaned Verification Workflow (`L65-L80`)**:
  - Students can upload external certificates via `+ Upload Certificate` (`submitCertificate()`), which sets `verified: false`, **but no page exists anywhere (Faculty, Authority, or CPM) to review, approve, or reject submitted certificates**. And the modal (`index.html:622-663`) has no file upload input for the actual certificate proof!
- **Popup Blocker Crash (`L147-L150`)**:
  - `downloadCertPDF()` calls `const win = window.open(...); win.document.write(html);` without checking if `win` is `null` (when popups are blocked, throws `TypeError: Cannot read properties of null`).

#### G. User Profile (`js/pages/profile.js`)
- **Broken External Links (`L166-L167, L185`)**:
  - `profFieldLink` and `renderAuthorityProfile` prepend `https://` blindly (`href="https://${val}"`). If a user enters `https://github.com/user`, the link becomes `https://https://github.com/user`.
- **Authority Profile Email Edit Bug (`L277-L280`)**:
  - Authorities can edit their email to any string (no `@vvce.ac.in` validation, no duplicate check) and changes are only saved to `vvce_users`, **not** synced to `approving_authorities` in Supabase.
- **Large Base64 Bloat (`L189-L194, L310-L315`)**:
  - Profile photos and PDF/DOCX resumes are stored as raw base64 data URLs directly inside the `users` table row (`profile_photo`, `resume`) with zero file-size limit or compression.
- **Two-Column Grid Not Responsive (`L49, L139, L153, L172`)**: Inline `grid-template-columns: 1fr 1fr` does not collapse on mobile screens.

### 7. Frontend ↔ Backend ↔ Database Connections & Security Gaps

#### A. Schema & Field-Mapping Mismatches
1. **`events` Column Case Mismatch (`database.js:148-187` vs `migration_approving_authorities.sql:24-30`)**:
   - `migration_approving_authorities.sql` adds snake_case columns: `authority_id`, `authority_name`, `approved_by_authority_id`, `approved_by_authority_name`, `approved_at`, `decision_history`.
   - `database.js:mapEventForSupabase()` sends **camelCase** keys (`authorityId`, `authorityName`, `approvedByAuthorityId`, `approvedByAuthorityName`, `approvedAt`, `decisionHistory`) on every `setDB('vvce_events', ...)`, causing PostgREST `400` schema errors!
   - `database.js:mapEvent()` (`L299-310`) **completely omits** mapping `authority_id`, `authority_name`, `approved_by_authority_id`, `approved_by_authority_name`, `approved_at`, `decision_history` back from Supabase!
   - `database.js:mapEventForSupabase()` also omits `waitlist`, `waitlist_enabled`, and `publish_at`.
2. **`add_team_columns.sql` Unquoted CamelCase Columns**:
   - `ADD COLUMN isTeamEvent ...` without double-quotes creates lowercase columns (`isteamevent`, `minteamsize`, `maxteamsize`) in PostgreSQL, mismatched against camelCase queries in JS (`isTeamEvent`, `minTeamSize`, `maxTeamSize`).
3. **Certificates Table Name Mismatch (`database.js:234-242` vs `types/supabase.ts:17-60`)**:
   - JS queries table `vvce_certs` with column `"userId"`, `auto_generated`, `event_id`; `types/supabase.ts` defines table `certificates` with `user_id` (and lacks `auto_generated`, `event_id`).
4. **Missing Migration Files**:
   - No SQL migration exists in `database/` for `users`, `registered_students`, `events` base table, `vvce_certs`, `academic`, `principal_status`, `principal_schedules`, `princ_attend`, `cpm_config`, `cpm_audit_logs`, or `cpm_backgrounds` bucket.

   - `api/send-otp.js` (`L98-101`) returns `200 { success: true }` even if neither `RESEND_API_KEY` nor `BREVO_API_KEY` is set in Vercel env vars (no email actually sent).
   - No auth check, rate limit, or server-side OTP verification — OTP verification happens solely in browser memory (`window._resetPasswordState.code`).
   - CORS allows `*` with `Access-Control-Allow-Credentials: true` (`L4-5`).

#### B. Critical Security Gaps Summary
- **Plaintext Passwords Stored & Broadcast**: `users` and `registered_students` store plaintext passwords (`pass`), and `bootApp()` downloads all user rows (including `pass`) into every student's browser.
- **Wide-Open Supabase RLS Policies**: `approving_authorities` allows `FOR ALL TO anon, authenticated USING (true) WITH CHECK (true)` (`migration_approving_authorities.sql:50-55`), and client code uses the public `anon` key directly for admin/CPM/user mutations without Supabase Auth JWT checks or role enforcement.
- **Client-Side Hardcoded Secrets**: `DEAN_PASS`, `PRINCIPAL_PASS`, and `Vvce@Admin#CPM2025` are exposed in client-side source files.
- **Missing XSS Sanitization**: User/admin inputs (`name`, `clubName`, `desc`, `rules`, `team.name`, `rejReason`, `banner.text`) are inserted raw into `innerHTML` across all pages.

### 8. Performance & Scalability Bottlenecks (5,000–6,000 Concurrent Users)

| Bottleneck | Where | Impact at 5,000–6,000 Users |
|---|---|---|
| **Unpaginated `select('*')` on 8 Tables + Supabase 1,000-Row Limit** | `js/core/database.js:475-484` (`bootApp()`) | Supabase PostgREST caps default `select('*')` at **1,000 rows**. Once >1,000 students register, **~4,000–5,000 students silently vanish** from `vvce_users`! Downloads massive payloads on every load. |
| **Repeated Full Boots on Focus/Tab Switch** | `js/main.js:25-33` (`pageshow`, `visibilitychange`) | Every browser tab switch re-triggers all 8 full-table `select('*')` queries + `checkSupabaseEmailVerification()`. With 5,000 students switching tabs, this creates **tens of thousands of heavy DB reads per minute**. |
| **`O(N)` Full-Table Upsert on Single Record Edits** | `js/core/database.js:206-263` (`setDB`) | Reading one notification (`readNotif`), sending one notification (`addNotifToUser`), editing a profile (`updateUser`), or registering for 1 event re-upserts **all 5,000+ users** (into both `users` and `registered_students`) or **all events**! Causes massive bandwidth spikes and lost-update overwrites. |
| **`DELETE ... NOT IN (...)` on Certificates** | `js/core/database.js:236-241` | Sends all certificate IDs in a query parameter (`414 URI Too Long` failure at scale) and creates race conditions where concurrent certificate writes delete newly added certificates. |
| **Base64 Images & PDFs Stored Inside Table Rows** | `events.js`, `create-event.js`, `profile.js`, `auth.js` | Event posters, payment screenshots, club logos, profile photos, and resumes are saved as base64 inside `users` and `events` JSON/text columns instead of Supabase Storage buckets — bloating single rows to multi-megabyte sizes and exceeding browser `localStorage` 5 MB limits. |
| **Global Realtime Storm Across All Clients** | `js/core/database.js:431-462` | Subscribes all 5,000+ clients to `postgres_changes` `event: '*'` on `users`, `registered_students`, `events`, `vvce_certs`, etc. Every single registration or notification broadcast triggers re-renders (`showPage`) across thousands of connected browsers simultaneously. |
| **Missing Database Indexes** | `database/*.sql` | No indexes defined on `users(email)`, `users(usn)`, `users(type)`, `events(status)`, `events(date, venue)`, `events(authority_id)`, `events(admin_id)`, or `vvce_certs("userId")`. |
| **No Pagination / Virtualization in UI** | `participants.js`, `events.js`, `authority-portal.js`, `cpm.html` | Renders all events and all participants into the DOM at once, plus `N+1` sequential HTTP notification updates in `cpm.html:1295-1300`. |
